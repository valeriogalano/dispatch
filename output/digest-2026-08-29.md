## AudioPills

### Fixed
- `d55750b` fix: run CI only on pull_request to stop double-billing macOS minutes (#39)
  Every commit was tested twice: once as the PR check, once again as a push to
  main right after the merge. Of the last 58 runs, 30 were pull_request and 28
  push, almost all of them pairs on the same commit.
  
  That is expensive here because the job runs on macos-latest, billed at 10x on
  a private repo: roughly 15-20 billed minutes per run for a build of about 90
  seconds. Dropping the push trigger halves it without losing coverage, since
  pull_request already validates the same commit before it lands.

### Changed
- `600d984` docs: record that CI is suspended and testing is local only (#42)
  The CI workflow is disabled_manually on GitHub: the Actions minutes are gone,
  and every run on macos-latest is billed at 10x on a private repo. The workflow
  file is untouched, so this is a switch, not a deletion — gh workflow enable CI
  brings it back.
  
  Written down because a disabled workflow looks identical to a broken one from
  inside the repo, and because the consequence is easy to miss: pull requests no
  longer carry checks, so the local run is the only verification there is and has
  to happen before every merge, not just before opening the PR.
  
  It also removes the last safety net under the "TEST SUCCEEDED with 0 tests
  executed" trap: with no CI comparing counts between runs, reading the number
  instead of the outcome is now the only thing that catches it.

## Instagram MCP

### Added
- `cc29172` feat: account-level insights and follower counts
  account_insights() answers 'how is the account doing' where media_insights
  answers 'how did this post do'. account_info() now also returns
  followers_count, follows_count and media_count.
  
  The account endpoint is not symmetric with the per-media one: it needs
  metric_type=total_value (without it you get a per-day series instead of
  totals) and its metric names differ -- saves rather than saved, plus
  profile_views and accounts_engaged which have no per-media equivalent.
  All verified against the live API rather than the docs.
- `bb157ac` feat: MCP server for Instagram comments and insights
  Reads comments and engagement figures from a professional account and
  replies to comments. It does not publish: that stays with
  podcast-audiogram-publisher, which runs in Actions with its own token.
  
  Uses the Instagram API with Instagram Login (graph.instagram.com) rather
  than the Facebook Login flavour, so no Facebook Page is involved and the
  token refreshes from code. Every off-the-shelf Instagram MCP server
  evaluated assumes the Facebook flavour, or has no token rotation.
  
  The token rotates itself in token.json once fewer than 7 days remain,
  which works because ig_refresh_token does not revoke the token it derives
  from -- that is what lets this server and the publisher hold independent
  credentials for the same account.
