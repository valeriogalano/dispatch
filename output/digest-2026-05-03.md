## Podcast RSS to Telegram
<https://github.com/valeriogalano/podcast-rss-to-telegram/commits>

### Fixed
- [`ba9b6e8`](https://github.com/valeriogalano/podcast-rss-to-telegram/commit/ba9b6e83177e54eb131d0d13c0a03a977b38f787) fix: hardcode environment name in workflow instead of using github.environment
  github.environment context is empty for workflow_dispatch events, causing
  update_github_variable to raise RuntimeError on every run. The LAST_PUBLISHED_URL
  was never saved, so the script republished the same episode indefinitely.
- [`53d7999`](https://github.com/valeriogalano/podcast-rss-to-telegram/commit/53d79999eb34e7c7ee2ca924c96d150dbb41c014) fix: raise on state-save failure, do not escape URL in Telegram message
  Two bugs caused Good Vibrations to keep republishing the same episode:
  
  1. update_github_variable() logged a warning and returned silently on any
     GitHub API error (403, 422, network issues). The main script then logged
     "Variabile di stato aggiornata." regardless, hiding the failure. Because
     LAST_PUBLISHED_URL was never saved, every cron run saw the episode as new.
     Fix: raise RuntimeError on API errors so the GitHub Actions job fails
     visibly and the operator knows state was not persisted.
  
  2. PR #7 (revert) re-introduced escape_markdown_v2() on the episode URL.
     When the template uses [text]({link}) format, Telegram MarkdownV2 requires
     the URL inside () to be unescaped; passing https://www\.spreaker\.com/ep\-42
     produces a malformed href. Fix: pass episode['link'] as-is (restoring
     the correct behaviour from PR #5).
  
  Also adds tests/test_github_state.py (0% coverage → 100%) and restores
  test_link_not_escaped_in_output removed by the revert.
- [`b8c0307`](https://github.com/valeriogalano/podcast-rss-to-telegram/commit/b8c0307d2e46905c5daef7603f335c51bff438c7) fix: force link preview via link_preview_options API parameter (#6)
  When the template uses [text]({link}) markdown format, Telegram
  creates a hyperlink but suppresses the link preview. Using
  link_preview_options.url forces Telegram to generate the preview
  for the episode URL regardless of how it appears in the template.
- [`e3f2026`](https://github.com/valeriogalano/podcast-rss-to-telegram/commit/e3f2026f55bb87119dfffc2a8fd72d38c01502e4) fix: do not escape {link} URL in Telegram message (#5)
  * fix: normalize literal \\r\\n escape sequences in TEMPLATE env var
  
  GitHub Actions expands multiline variables as literal \r\n strings.
  In Telegram MarkdownV2, these are interpreted as escaped characters
  and rendered visibly as 'rn'. normalize_template() converts them to
  real newlines before the message is sent.
  
  * fix: do not escape {link} URL in Telegram message
  
  Escaping URLs with MarkdownV2 rules (e.g. \. \-) breaks Telegram's
  URL auto-detection and prevents the link preview from appearing.
  URLs must be passed as-is; only title and hashtags need escaping.
- [`17186a5`](https://github.com/valeriogalano/podcast-rss-to-telegram/commit/17186a5dbe0478790775eab6b9f78e6c53d9e3f9) fix: normalize literal \\r\\n escape sequences in TEMPLATE env var (#4)
