### Fixed
- `93ebabf` fix: landscape rotation, speech audio session, video playback
  Three defects found running the app on a physical iPhone.
  
  Rotation was taken from the UIDeviceOrientation table while reading a
  UIInterfaceOrientation. The two enums name the landscape cases the
  opposite way round, so landscape preview and recording came out upside
  down. Portrait is identical in both enums, which is why nothing looked
  wrong until the device was turned. The tests agreed with the mistake
  because they were written from the same assumption; they now state which
  enum the angles belong to.
  
  Speech scrolling stopped working after the microphone routing was
  centralised: start() used to re-assert the audio session on every call,
  while configureSessionIfNeeded() is a no-op after the first. An
  AVCaptureSession owns the audio session while it runs and can leave it
  deactivated, so the engine was starting onto silence. Added
  AudioInputCatalog.activateSession() and called it before each start.
  
  The recordings player was built inside body, so every redraw replaced it
  with a fresh, paused one and playback never got past the first frame.
  It is held in @State now and starts on appear.
- `a178967` fix: show scripts created with empty content
  The editor requires a title but not a body, while loadScripts skipped any
  .md whose trimmed content was empty. "New Script" therefore wrote a file
  that never appeared in the library, and the name stayed taken: a second
  attempt at the same title was refused as a duplicate, pointing at a
  script the user could not see anywhere.
  
  Only unreadable files and iCloud placeholders are skipped now.
  
  Found during manual verification of the previous fixes; predates them,
  but the duplicate-title guard added there turned an invisible file into a
  blocked title.

- `f3305e5` fix: Save As wrote nothing when called without a completion
  Adding the completion parameter in 519c699 turned the write into
  completion?(writeProject(to: url)). Optional chaining does not evaluate
  its arguments when the optional is nil, so with no completion supplied —
  which is every call from File > Save Project As — the panel returned a
  URL, the path was adopted as the current project, and nothing was ever
  written. No file, no error.
  
  The close-project alert passes a completion, so that path kept working,
  which is why manual checks of the confirmation dialog did not catch it.
  
  The write now happens in its own statement before the completion is
  called. It also moves into saveProject(to:), so the half that does the
  work can be tested without driving an NSSavePanel, and two tests now
  cover it: one asserts the file appears with the expected contents, the
  other that saving with nothing loaded fails loudly.
  
  That second case was silent too: writeProject returned early when there
  was neither a feed nor an audio path, leaving the user with no file and
  no message. It now reports the error.
- `18f9369` fix: keep the waveform bucket boundaries bit-identical to the previous pass
  The streaming rewrite assigned a sample to Int(frame / framesPerBucket),
  while the previous implementation walked bucket i over the half-open
  range [Int(i * framesPerBucket), Int((i+1) * framesPerBucket)). The two
  round differently at the edges: compared on the same file, 17 of 663
  buckets held a peak one bucket away from where it used to be — the
  amplitudes were unchanged, but a peak could be drawn up to 10ms off.
  
  Restores the original partition with a running boundary, so the buckets
  now match the previous output exactly. Verified by extracting the same
  file with both implementations and diffing the base mipmap: 0 differing
  buckets, where the divide-per-sample version had 17.
  
  Matters because the waveform rendering is untouched work: a refactor
  done for memory should not move what it draws.
- `4b0b7a7` fix: stop granting cross-origin access to the MCP endpoint
  Responses carried Access-Control-Allow-Origin: * and the preflight
  advertised POST, so any web page the user happened to open could drive
  the unauthenticated tools on 127.0.0.1:7890 — read the project, edit
  soundbites, spend LLM API credit.
  
  No MCP client needs those headers: the stdio bridge, Claude Code and
  Cursor are local processes and never consult CORS. Only a browser does,
  and withholding the headers is precisely what makes it refuse. The
  preflight is still answered, just without granting anything.
- `26b67c7` fix: drain the Gemini CLI pipes concurrently
  waitUntilExit() ran before the pipes were read, so a CLI writing more
  than the ~64KB pipe buffer blocked on write and the app hung forever.
  
  Reading stdout to EOF first is not enough on its own: the child can be
  blocked writing stderr, which nothing is draining yet, and the wrapper
  then waits on a stdout EOF that never comes. Measured against a child
  flooding both streams, that ordering deadlocks exactly like the original
  one. stderr is now read on a background queue while stdout is read here,
  which holds with 2MB on both streams.
- `7cb17f4` fix: check download responses, cancel transfers, refresh derived state
  Podcast downloads accepted any response body: a 404 or an error page was
  stored under the episode's audio name and, because the cache only tests
  for existence, was reused forever without retrying. Both downloadAudio
  and downloadTranscript now require a 2xx status.
  
  Cancelling a download only cancelled the Swift task while the
  URLSessionDownloadTask kept transferring. The transfer is now tied to
  task cancellation through withTaskCancellationHandler; the URLSessionTask
  is started inside the shared handle so a cancellation arriving before
  resume() is not lost, and the resulting URLError.cancelled is treated as
  a cancellation rather than surfaced as a download failure.
  
  Also:
  - transcriptSegments clears the soundbite text cache on assignment. The
    cache was keyed on the time range alone and never emptied, so after
    switching episode a range already seen showed the previous episode's
    words.
  - loadProject reports an error and clears isLoading when the file has
    neither a feed nor an audio path, instead of spinning forever, and
    refuses a feed with no episodes instead of subscripting an empty array.
  - The feed parser resets the soundbite start/duration when a tag opens,
    so a tag missing an attribute no longer inherits the previous one.
  
  Verified with the app running against Scripts/verification-fixtures.sh:
  the 404 enclosure reports HTTP 404, a cancelled download makes the server
  log ABORTED at 25% with no error alert, the same time range shows each
  episode's own words, and the audio-less project reports an error.
- `0037419` fix: remove the duplicate add-soundbite menu item and free Cmd+W
  "Add Soundbite" and "Quick Add at Playhead" both called addPill(), so
  the menu offered the same action twice under labels that promised
  different behaviour. "Close Project" also occupied Cmd+W, the system
  shortcut for closing a window, so closing the window unloaded the
  project instead.
  
  Keeps a single "Add Soundbite" item on Cmd+N and moves "Close Project"
  to Cmd+Shift+W. The bare "I" shortcut disappeared with the duplicate
  item; the in-app help is updated accordingly. If the single-key binding
  is wanted back, it belongs on the remaining item.
- `7e2cc80` fix: bind the MCP server to the loopback and harden its HTTP parsing
  The listener was created without constraining the interface, so the
  server was reachable from the whole local network with no authentication
  at all, while its tools can read the project, edit soundbites, write
  files and spend LLM API credit.
  
  Binding the endpoint carries the port, so NWListener(using:) must be
  used without the `on:` argument — passing both prevents the listener
  from ever reaching .ready, which silently disables the server.
  
  Also in this commit:
  - tryParseRequest now distinguishes an incomplete request (keep the
    buffer, wait for more bytes) from a malformed one (drop the buffer and
    answer 400). Previously a malformed request left the connection
    re-parsing the same bytes forever.
  - The header/body split is done on the raw bytes and only the header
    section is decoded as UTF-8. The body offset was derived from a UTF-16
    string offset applied to a byte buffer, and a non-UTF-8 body made the
    whole request fail to parse.
  - stop() cancels the open connections, which the previous empty
    forEach did not, and accesses to the connections dictionary are
    serialised on the existing queue instead of racing between the network
    queue and the main thread.
  
  Verified with the app running: netstat reports 127.0.0.1.7890 instead of
  *.7890, requests from the LAN address are refused, requests from
  127.0.0.1 and a round trip through AudioPillsMCPBridge still work, and a
  malformed request now returns 400 with the server still healthy. The
  connection teardown in stop() is reviewed but not exercised at runtime.
- `22eb5ab` fix: avoid a trap when waveform data has no mipmaps
  samplesForLevel clamped the level with max(0, min(level, count - 1)),
  which yields 0 for an empty mipmaps array and then traps on subscript.
  extractWaveform returns exactly that shape for a zero-frame file, for a
  bucket count of 0, or when the PCM buffer cannot be allocated.
  
  The existing test used mipmaps: [[]] — one empty level — so the case
  that actually traps was not covered; the new test uses mipmaps: [].
- `64f2753` fix: parse VTT and SRT transcripts with CRLF line endings
  Cues are split on "\n\n", so a Windows-authored file (which separates
  them with "\r\n\r\n") collapsed into a single block: only the first cue
  was read and the remaining lines were absorbed into its text. Transcript
  files served by podcast feeds are frequently generated on Windows.
  
  Line endings are now normalised inside parseVTT and parseSRT, where the
  split happens, so direct calls to either parser are covered too and not
  just the ones routed through parse(content:mimeType:).
- `7792280` fix: use the real decimation rate for micro-pause times
  extractRawSamples decimates by an integer factor, so at 44.1 kHz the
  envelope is sampled at 1002.27 Hz rather than the 1000 Hz that
  detectMicroPauses assumed, and its sampleRate parameter was ignored
  entirely. Times were short by 0.23% — roughly 8 seconds over an hour,
  enough to make snap-to-pause miss on long episodes.
  
  extractRawSamples now returns the effective rate alongside the samples
  and detectMicroPauses uses the rate it is given. Also promotes the two
  unused pauseAmplitudeThreshold/minimumPauseDuration constants to static
  and uses them at the call site, which had the values hardcoded.
  
  Covered by detectsPauseAtActualDecimationRate, which fails on the
  previous implementation.

  so over a gigabyte of peak usage, to produce a few megabytes of output —
  and the file was decoded twice to do it.

  goes. Outputs are preallocated from the file length and every sample is

  bucket or an envelope block. Peak memory is now a function of the chunk,
  not of the file.
