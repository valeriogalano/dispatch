### Fixed
- [`0e365a1`](https://github.com/valeriogalano/dispatch/commit/0e365a1968ce0390f747f4f27b4e96e59a4ef2d5) fix: harden the pipeline and deduplicate the recap workflows
  - collect.py: a 403 without rate-limit headers is a permission error, not a
    quota one, and retrying it forever hung the job until the GitHub timeout.
    Wait only on a real rate limit (Retry-After or exhausted quota), cap the
    sleep at an hour and bound the number of waits. 429 is handled too.
  - collect.py: "!" was read as a breaking-change marker even in commits with
    no conventional prefix, so "fix crash on empty input!" became Breaking.
  - collect.py: the manual-notes window was inclusive on both ends, so a note
    dated on the boundary day was published in two consecutive digests.
  - recap.py: a missing API key was raised inside the retry loop and slept for
    a minute before failing over; providers without their key are now skipped
    at once. Gemini is imported lazily, like Anthropic already was.
  - publish_telegram.py: a recap over 4096 characters got a 400 the plain-text
    fallback could not rescue, breaking the chain. Long recaps are split.
  - One reusable _generate-recap.yml replaces the two nearly identical recap
    workflows; requirements.txt pins the dependencies the workflows installed
    unpinned; a Tests workflow finally runs the suite; the weekly job prunes
    output/ beyond 52 weeks.

  error, blanking `<language>` in all three feeds, `<html lang>` on every
  page and `og:locale`. Config and the five template reads therefore change
  together.
  
  The reads used two different forms, `.Site.LanguageCode` and
  `site.Language.LanguageCode`; grepping for the first alone misses the two
  RSS templates.
  
  Verified by rebuilding the whole site and diffing against a pre-change
  baseline: byte-identical except for `lastBuildDate`. `<language>it-IT</language>`
  in all three feeds, `lang="it-IT"` on 590 pages with none empty, and
  `og:locale` still `it_IT`.
  
  One deprecation warning remains and is out of scope here: it comes from
  podcast-feed-hugo v0.2.0 (`layouts/podcast/list.rss.xml`), already fixed
  upstream in v0.3.0.

## Podcast Feed Hugo
<https://github.com/valeriogalano/podcast-feed-hugo>

### Breaking
- [`37bbcad`](https://github.com/valeriogalano/podcast-feed-hugo/commit/37bbcad782983b9144690078acc9f7d4cc4abff6) feat!: rename episode "audio" field to "audio_file", move demo to exampleSite/
  BREAKING CHANGE: the episode front matter field "audio" is now "audio_file",
  and the demo site moved from the repository root to exampleSite/.
  
  Hugo's embedded _internal/opengraph.html template ranges over .Params.audio,
  which it documents as []string because Open Graph allows repeated og:audio
  tags. Sites including that template - most themes do - failed to build with
  "range can't iterate over ..." when following the documented front matter,
  where "audio" is a plain string. A podcast episode has exactly one audio
  file, so rather than forcing a single-element list onto a name Hugo already
  uses with another type, the field moves to "audio_file". It sits alongside
  the unchanged "audio_duration" and "audio_size".
  
  The demo site (content/, static/, config.toml) lived at the repository root,
  and Hugo mounts every standard directory of an imported module by default,
  so consumers importing this module without explicit mounts inherited four
  demo episodes, their MP3 files, images and a stray .htaccess. Verified on a
  minimal consumer site: 9 pages and 10 static files before, none after.
  
  The demo now builds from exampleSite/, consuming the module through a local
  replace directive, so it still exercises the shipped layouts. The Pages
  workflow builds with --source exampleSite and installs Go, which Hugo needs
  to resolve the module import.

### Added
- [`c0df34b`](https://github.com/valeriogalano/podcast-feed-hugo/commit/c0df34b7acf4799b5a052bc115fd9128b4aa29f4) feat: declare minimum Hugo version in module config
  Since v0.3.0 the module uses `.Site.Language.Locale` in
  `layouts/podcast/list.rss.xml`, which replaced the `.Site.LanguageCode`
  deprecated in Hugo v0.158.0. Without a declared constraint, importing the
  module with an older Hugo produced an obscure failure instead of a clear
  message.
  
  `Locale` is documented as "New in v0.158.0" in the Hugo docs for
  Site.Language, and the v0.158.0 release notes introduce it as the
  replacement for the deprecated `.Site.LanguageCode`, so that is the floor.
  
  Since v0.3.0 the module has no root config file (it moved to
  `exampleSite/config.toml` so importers do not inherit the demo content),
  so this adds a root `hugo.toml` holding only the `[module]` section. No
  explicit mounts are declared: they would replace the defaults and break
  the exposure of `layouts/` and `archetypes/`.
  
  Verified with a minimal consumer site importing the module: it builds,
  only its own content appears, `exampleSite/` is not mounted, the module
  still exposes `layouts/` and `archetypes/`, and `.Site.Language.Locale`
  renders. Temporarily raising `min` to an unreachable version confirms the
  constraint is read and reported clearly (as a WARN, not a hard error).
