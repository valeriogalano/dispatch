- [`8a2d77f`](https://github.com/valeriogalano/AudioPills/commit/8a2d77f8d548d85b27f4827ccdb2255fb2b5c049) feat: add embedded MCP server with 31 tools for AI client integration
  Exposes AudioPills functionality via Model Context Protocol (MCP) over
  HTTP on localhost:7890. AI clients (Claude, Gemini, ChatGPT, Cursor, etc.)
  can control the app using JSON-RPC 2.0 via a single POST /mcp endpoint.
  
  Tools implemented:
  - Soundbites: list, get, create, update, delete, duplicate, import, export,
    restore_feed, get_feed_pill_status
  - Episodes: list_episodes, get_episode, set_episode, refresh_feed
  - Transcript: get_transcript, get_transcript_segment_at
  - Playback: play, pause, seek, play_loop, play_soundbite
  - Waveform: get_micro_pauses, snap_to_pause
  - Project: get_project_info, save_project, list_recent_projects
  - AI: generate_soundbite
  - Cache: get_cache_info, get_download_cache_info, remove_download, clear_cache
  
  Settings: toggle in General tab starts/stops the server; dedicated MCP tab
  provides auto-configure for Claude Desktop, command copy for Claude Code,
  and URL copy for Cursor and other clients.
  
  Entitlement com.apple.security.network.server added for NWListener sandbox access.

- [`e0cc653`](https://github.com/valeriogalano/AudioPills/commit/e0cc653c027e0858efb8a9cc9f34ae1d28b444f9) fix: add --scope user to claude mcp add/remove commands for global registration
- [`d280f6d`](https://github.com/valeriogalano/AudioPills/commit/d280f6d53c693048553ea813f878777142579115) fix: implement LSP Content-Length framing in AudioPillsMCPBridge
  Claude Desktop's stdio MCP transport requires LSP-style message framing
  (Content-Length: <n>\r\n\r\n<body>), not plain newline-delimited JSON.
  The bridge now reads headers byte-by-byte to extract Content-Length,
  reads exactly that many bytes for the body, and wraps responses with
  the same Content-Length header before writing to stdout.
- [`5735474`](https://github.com/valeriogalano/AudioPills/commit/57354745e427d9077abfaf7e42f3ce33998a8f32) fix: remove+add claude mcp server to handle already-exists case
  'claude mcp add' exits 1 if the server already exists. Fix: run
  'claude mcp remove audiopills' first (ignoring failure), then re-add.
- [`7e14234`](https://github.com/valeriogalano/AudioPills/commit/7e1423427170abfe861e0e4d646b2ad6a0617339) fix: revert NSMutableDictionary cast that always failed
  JSONSerialization returns NSDictionary (immutable). Casting to
  NSMutableDictionary always returns nil in Swift, triggering the
  error guard. Reverted to [String: Any] which bridges correctly.
- [`de45b30`](https://github.com/valeriogalano/AudioPills/commit/de45b3036bd5921de5baef70d11a9764f742be71) fix: remove isRunning guard from config buttons, fix claude PATH lookup
  Buttons were always disabled because the optional chain viewModel.mcpServer?.isRunning
  is not reliably observed by SwiftUI. Claude Desktop config does not need
  the server running. Claude Code now finds the claude binary by searching
  common install paths instead of relying on the app's limited shell PATH.
- [`1d6a628`](https://github.com/valeriogalano/AudioPills/commit/1d6a6286721abc042b6883daac77f27baf76f054) fix: add "type": "http" to Claude Desktop MCP config entry
  Claude Desktop requires an explicit type field for HTTP transport servers.
  Without it the entry is silently ignored with a validation warning.
- [`e8b7a5f`](https://github.com/valeriogalano/AudioPills/commit/e8b7a5fdc4ce8182389828e928c480f61427d9e3) fix: use NSMutableDictionary for safe JSON merge in Claude Desktop config
  Swift cast to [String: Any] can fail on complex nested structures returned
  by JSONSerialization (NSDictionary with NSArray children). Using
  NSMutableDictionary directly avoids the cast issue and guarantees the
  existing mcpServers entries (phpstorm, pycharm, etc.) are preserved.
