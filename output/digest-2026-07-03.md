- [`307f4fa`](https://github.com/valeriogalano/podcast-audiogram-automation/commit/307f4fa6b99a3ddaccf8f56444378ce55d1ef7fd) fix: committa lo stato pubblicazioni anche su fallimento parziale (#5)
  Il publisher salva published.json su disco dopo ogni piattaforma
  pubblicata con successo (state.mark_published -> _save immediato). Se

  published.json, quindi un fallimento totale (nessuna pubblicazione) non
  produce commit.

## Podcast Audiogram Generator

### Added
- [`91ff335`](https://github.com/valeriogalano/podcast-audiogram-generator/commit/91ff335cc32208065ecddea32afab27254b89e9b) feat: add caption_transcript option to position the transcript in the .txt (#2)
  Introduce the 'caption_transcript' config option (inline | last | none)
  to control where the transcript is placed in the .txt caption file:
  - inline (default): current behavior, before the listen link
  - last: the transcript becomes the final block, after the hashtags
  - none: the transcript is omitted from the .txt (still written to the .srt)
  
  The value is validated in the CLI with a fallback to 'inline'. Default
  behavior is unchanged.

  Adds unit tests for _build_message_caption.
- [`77a9bfe`](https://github.com/valeriogalano/podcast-audiogram-publisher/commit/77a9bfea771dd299039018ad688c43d1f580a2cd) feat: post long videos as a message when they exceed the Telegram Story limit (#2)
  Telegram Stories only accept videos up to 60 seconds; longer videos are
  rejected with RPCError 400 VIDEO_DURATION_INVALID. Probe the video
  duration with ffprobe and, when it exceeds story_max_duration (default
  60), post a normal video message to the peers instead of a story.
  
  If the caption is longer than the media caption limit
  (message_caption_limit, default 1024) it is truncated on a word boundary
  with an ellipsis.
  
  Adds unit tests for the pure helpers (_use_story, _truncate_caption)
  and documents story_max_duration / message_caption_limit.

  The SQLite schema has no FOREIGN KEY/ON DELETE CASCADE, and
