## Agent Skills

### Added
- `cc3b2f5` feat(global): Codex reads the same instructions, under its own filename
  link-skill.sh now links global/CLAUDE.md to ~/.codex/AGENTS.md as well: one
  source, two names, since each client looks for a different filename.
  
  ~/.codex/AGENTS.md already existed as a real file with its own rules, and the
  guard refused to overwrite it, which is what it is for. Its commit rules were
  already covered here; its changelog section was more detailed, so those details
  are merged in first: the Keep a Changelog headings, the mapping from Conventional
  Commit prefixes to sections, and writing entries for the user rather than copying
  the commit subject.
- `ac0b36f` feat(global): version the always-loaded instructions and link them from here
  ~/.claude/CLAUDE.md was the only piece of the setup that was not versioned: a
  plain file, no history, absent on a new machine. It now lives in global/ and is
  symlinked back by link-skill.sh, the same source-of-truth rule the skills follow.
  
  It stays out of the repo root on purpose: a CLAUDE.md next to AGENTS.md would be
  read as the instructions of this repository, which it is not.
  
  The split it makes explicit is worth keeping in mind when placing a new rule. A
  skill loads only when its description matches the request, so a rule that must
  apply on every tracker cannot live in one tracker's skill. Those go here.
  
  Also drops from the INVALSI client sheet the two Azure rules it had copied out of
  vcs-platforms, leaving the pointer.
- `2239e89` feat: add clienti skill, and scope task creation by project kind
  The clienti skill answers who is on the other side of each project: who is the
  intermediary, who is the end client, who does what, which tracker carries the
  conversation, and what is explicitly not Valerio's to do. Rediscovering that
  every session costs turns and produces concrete errors: quoting work someone
  else in the chain already does, addressing a tracker reader as if they were the
  end user, or proposing a change to a component that is not his.
  
  Structure follows local-resources: an index in SKILL.md with a division of
  sources, one reference file per client read on demand. Credentials stay in
  Proton Pass and the Azure org map stays in vcs-platforms, pointed at rather than
  copied. Covers GutenMind/Moveo Telepass, INVALSI and Devdata/IFO.
  
  issue also gains the threshold for opening a task. On personal projects a task
  is not needed to work on something: it only carries state between sessions, so
  anything that can be resolved on the spot does not become one. On client
  projects the task is proposed rather than assumed.

### Fixed
- `84d11f2` fix(bin): pass MCP tokens through the environment, not argv
  The token travelled as a `--header` argument, and argv is readable with `ps` by
  any other user on the machine: the GitHub PAT and the Obsidian API key were on
  display for as long as the MCP server ran. `mcp-remote` expands `${VAR}` inside a
  header value, so the header keeps its shape while the secret stays in the
  environment of the process.

- `9ad5af3` docs(vcs-platforms): effort goes in two fields, estimate and remaining
  On the INVALSI organisations the client reads the estimates in the sprint view,
  and an item without `Remaining Work` weighs zero in the burndown: an estimate
  written only in `Original Estimate` is invisible exactly where it is meant to be
  seen. Both fields get the same figure on creation, derived from the Todoist
  estimate and doubled, because Todoist holds what the work itself takes while the
  tracker holds what is committed to a client, interruptions and review included.
  
  `Remaining Work` moves as the work goes, `Original Estimate` never does — the gap
  between them is the only part that teaches anything. `Completed Work` is filled on
  closing with the hours actually spent, so it is not doubled. Closed items are not
  backfilled: reconstructed numbers are precise and false.
- `3e2f8d3` docs(git-workflow): read the repo's language policy, do not recall it
  A stated policy is a decision, so it holds even when it reads as inconsistent with
  the commits around it. Drops the invalsi-dwh-export-app example, which described
  that repo's rule from memory and had gone stale.
- `f78b22d` docs(proton-pass): put the recovery command first
  Every authentication failure has the same one-line fix, but it was buried in a
  troubleshooting table at the bottom, so the search for it ran through the session
  directory, the Keychain and the shell profiles first — paths that never hold the
  token and that look like a broken setup on the way. The section now opens the
  skill, and the description says out loud that this file answers `non-existent
  session`, `SessionLocked` and `failed to authenticate`.
  
  Also records that `pass-agent-secret` suggests `pass-cli agent renew` when its own
  login fails, and that the suggestion is wrong: renewing mints a new PAT and
  invalidates the working one in the Keychain.
- `4f59e34` docs(vcs-platforms,git-workflow): preview client-facing text before publishing
  Anything landing on a client's tracker now gets shown to Valerio first and waits
  for his go-ahead: PR titles and descriptions, work item descriptions, comments on
  work items and PRs, state changes carrying a comment, and new work items. The text
  goes out under his name, so he reads it before it is his, and on most trackers a
  comment notifies its watchers the moment it is posted — editing afterwards does
  not un-send it.
  
  Field edits are covered too when a reader acts on them: logged hours, assignment,
  iteration, priority. On top of the preview, `CompletedWork` must never be derived:
  session length, commit count and timestamps say nothing about how long the work
  took, and an invented number stops reading as a guess the moment it lands. The
  estimates stay as they were, computed from the Todoist figure by the rule under
  "Effort: two fields, always both".
  
  Todoist and the Obsidian vault are exempt: they are Valerio's own systems.
