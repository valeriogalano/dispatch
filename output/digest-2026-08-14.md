## Highlighter

### Added
- `fbc4ce8` feat: store book covers with the book
  Covers were only a URL: every view fetched them through AsyncImage, so they
  reloaded at each launch and were missing offline. Sizing URLCache was not
  enough — HTTP caching is transport, not storage, and nothing guaranteed the
  bytes were still there.
  
  Book.coverImageData (model version 4, external storage) now holds them.
  BookCoverImage renders the stored bytes and downloads them once for books that
  have none, so existing libraries fill in as they are browsed. Search results
  keep using AsyncImage: they are not stored books yet.
- `2c28e07` feat: choose what a shared highlight carries, for text and image alike
  Title and author, page number, and note are now toggles, and the same choice
  drives both outputs: HighlightShareContent is read by ShareExporter and by the
  quote card renderer, so the two cannot drift.
  
  Both outputs also share one screen. The action sheet that forked into "as
  image" / "as text" is gone: format is a selector at the top of the share
  screen, card styling shows only for Image, and the text output gets a preview.
  
  The card footer was already laid out bottom-up, so omitted blocks reflow on
  their own; the rule above it is skipped when the footer ends up empty.
- `8efcd60` feat: let one-shot export omit the book details
  Title, author, year, and ISBN were always emitted. A new Book details toggle
  drops them from every format: Markdown front matter, the text/RTF/PDF header,
  and the trailing CSV columns.
  
  Scoped to the one-shot export on purpose. Managed folders keep rendering with
  BookRenderOptions.syncDefault, so folder output and the fingerprint that drives
  "needs update" are untouched.

### Fixed
- `771c30c` fix: give book covers a cache big enough to survive relaunches
  Covers exist in the store only as a URL and are loaded by AsyncImage on every
  appearance, so the shared URLCache is the only thing standing between the
  library and a full re-download at each launch — and it was never configured,
  leaving the small iOS default. Open Library serves covers with
  "cache-control: public" and a far-future expiry, so cached copies stay valid.
- `7b0ec3a` fix: stop printing the app name in place of a missing page number
  A highlight without a page fell back to "Book Highlighter" in the card footer,
  putting the app's own branding on a shared quote. Omit the line instead; the
  footer already reflows around missing blocks.
- `cff431d` fix: send the bundle identifier with Google Books requests
  The shipped key is restricted to the app's iOS bundle ids, and Google rejects
  such a key with 403 "Requests from this iOS client application <empty> are
  blocked" unless the caller sends X-Ios-Bundle-Identifier. Verified against the
  live API: 403 without the header, results with it.
- `f780699` fix: show which sort order the library list is using
  A menu row renders only one image, so the checkmark added next to the row's
  Label was dropped and no option looked selected. Use a Picker, which marks the
  selection itself, and drop the per-row icons that were competing for that slot.
- `a720f02` fix: keep library sort order applied after relaunch
  Mutating the @FetchRequest's nsSortDescriptors did not reliably re-sort and
  reverted to "Date added" on the next launch. Persist the raw String and sort
  in memory instead, so the view stays reactive to the stored choice.

## AudioPills

### Fixed
- `2a093a1` fix: default the Claude provider to Sonnet rather than Opus
  Picking soundbites is a long-input, tiny-output judgement task. Running the
  app's own prompt across Opus 5, Sonnet 5 and Haiku 4.5 produced the same
  segment choices at every tier, differing only in the wording of the title,
  so the Opus default was paying for capability the task does not consume.
  
  Sonnet 5 costs roughly 40% less per generation on a transcript-sized input.
  The model remains user-configurable for anyone who wants to trade cost for
  capability on harder material.
- `b45f9bf` fix: repair the Claude integration (retired model, thinking blocks)
  The Claude provider had two independent defects that each broke it outright.
  
  The shipped default model was claude-sonnet-4-20250514, which Anthropic
  retired on 2026-06-15; every request returned HTTP 404 "model not found".
  The default is now claude-opus-5, and a stored value pointing at any known
  retired model is replaced on load so users who persisted the old one are
  migrated rather than left broken.
  
  Extracting the answer read content[0]["text"], but models with thinking
  enabled emit one or more thinking blocks before the text block, so the
  lookup returned nil and the provider threw invalidResponse. It now takes
  the first block whose type is "text".
  
  Both paths verified against the live API with the transcript prompt the app
  actually sends; ChatGPT (gpt-4o-mini) was tested on the same prompt and
  needed no change.

### Changed
- `cf77a52` Merge branch 'refactor/api-keys-keychain'
- `b886052` refactor: store LLM API keys in the Keychain instead of UserDefaults
  The ChatGPT, Claude and Gemini API keys were persisted as plain strings in
  the preferences plist, readable by any process with access to the user's
  home directory. They now live in the Keychain as generic passwords scoped
  to the app's own access group, which needs no extra entitlement under the
  sandbox.
  
  Keys already stored by previous builds are migrated on first read and the
  plaintext copy is removed from UserDefaults. README already documented the
  Keychain as the storage location, so no doc change is needed.
